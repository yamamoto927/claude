# 競馬 穴馬発見AI (keiba-ai)

netkeiba の出馬表と馬柱をスクレイピングし、指定レースについて

1. **荒れる可能性**(上位人気で決着するか／穴馬にもチャンスがあるか)をパーセンテージで
2. **穴馬筆頭候補**(最大3頭)とその根拠を

出力する CLI ツールです。あわせて想定ペース・本命/対抗・危険な人気馬・全頭評価・推奨買い目も出します。
**当日の馬場傾向をユーザーが入力すると、それが全評価に反映されます。**

---

## クイックスタート

```bash
pip install -r requirements.txt

# ネット接続なしで動作を確認する(サンプルレース)
python -m keiba_ai --sample --bias "内有利で前残り、時計はかなり速い"

# 実際のレースを分析する
python -m keiba_ai 202605021711 --bias "外差しが決まる荒れ馬場"

# 出馬表URLをそのまま渡してもよい
python -m keiba_ai "https://race.netkeiba.com/race/shutuba.html?race_id=202605021711"

# 馬場傾向を対話形式で入力する
python -m keiba_ai 202605021711 --interactive
```

`race_id` は netkeiba の出馬表 URL に含まれる12桁の数字です
(`https://race.netkeiba.com/race/shutuba.html?race_id=**202605021711**`)。

必須の依存は `requests` と `beautifulsoup4` だけです。`lxml` は入っていれば解析に使いますが、
C拡張のためホイールが無い環境(スマートフォンなど)ではインストールできないことがあります。
その場合は標準ライブラリの `html.parser` に自動で切り替わるので、そのまま動きます。

```bash
# lxml が入らない環境ではこれで十分
pip install requests beautifulsoup4
```

画面が狭いので、テキスト表(【7】全頭評価一覧)は横向きにするか `--markdown` / `--json` を使ってください。

## 馬場傾向の入力

当日の馬場傾向は **3軸**(いずれも `-1.0` 〜 `+1.0`)に落とし込まれます。

| 軸 | `+1.0` | `-1.0` |
|---|---|---|
| `inner` | 内(イン)有利 | 外有利 |
| `front` | 前残り | 差し・追込有利 |
| `speed` | 高速馬場 | 時計のかかるタフな馬場 |

### 1. 自然文で渡す(推奨)

```bash
python -m keiba_ai 202605021711 --bias "内有利で前残り、時計はかなり速い"
#=> 内有利(+0.80) / 前残り(+0.80) / 高速馬場(+1.00)
```

認識する表現の例:

* 内外 — 内有利 / イン有利 / ラチ沿い / 最内 / 内は荒れている / 外差し / 外枠有利 / 四分どころ
* 脚質 — 前残り / 逃げ有利 / 先行有利 / 前が止まらない / 差し有利 / 追込有利 / 後方一気 / 前崩れ
* 時計 — 高速馬場 / 時計が速い / 軽い馬場 / 時計がかかる / タフな馬場 / 道悪 / 消耗戦 / 荒れ馬場

「かなり」「極端に」「やや」「若干」などの修飾語は、**直後の表現だけ**に掛かります
(`内有利で時計はかなり速い` → 内は 0.80、時計は 1.00)。
`不良` `重馬場` `稍重` `良馬場` を含めると馬場状態そのものも上書きします。

### 2. 数値で渡す

```bash
python -m keiba_ai 202605021711 --bias-inner 0.6 --bias-front -0.4 --bias-speed -0.3 \
                                --bias-condition 重 --bias-confidence 0.7
```

数値指定は自然文より優先されます。`--bias-confidence` は傾向の確信度(0.0〜1.0)で、
補正の強さ全体に掛かります。まだ馬場傾向が読み切れない1〜2レース目は下げてください。

### 3. 対話形式

```bash
python -m keiba_ai 202605021711 --interactive
```

自由入力 → 空欄なら5段階の選択式に切り替わります。

### 馬場傾向が反映される先

* **枠順評価** — `inner` × 馬番の内外
* **脚質評価** — `front` を展開予想と 4:6 で合成し、逃げ/先行/差し/追込に加減点
* **時計適性** — `speed` が正なら切れ味型を、負なら道悪・消耗戦実績のある馬を加点
* **馬場状態適性** — `--bias-condition`(または「不良」等の語)で馬柱の集計対象を切り替え
* **荒れる可能性** — 馬場傾向と上位人気3頭の相性が悪いほど波乱度が上がる

## 出力される項目

| # | 項目 | 内容 |
|---|---|---|
| 1 | 荒れる可能性 | 波乱度(%)と、上位人気での決着確率(%)。増減の内訳つき |
| 2 | 穴馬筆頭候補 | 荒れる判定なら3頭、堅い判定なら1頭。データを引用した根拠つき |
| 3 | 想定ペース・展開 | 逃げ/先行頭数から算出したペースと前後有利度 |
| 4 | 馬場傾向の反映 | 入力値と、システムがどう解釈したか |
| 5 | 本命・対抗 | 能力7.5:市場2.5 の総合力。「危険な人気馬」は除外 |
| 6 | 危険な人気馬 | 人気の割に評価できない馬とその理由 |
| 7 | 全頭評価一覧 | 能力 / 市場 / 乖離 / 穴指数 / 脚質 |
| 8 | 推奨買い目 | 波乱度に応じた券種と組み立ての方針 |
| 9 | データ上の注意 | 取得できなかった項目など |

出力形式は `--format text`(既定) / `markdown` / `json`。`-o FILE` でファイルに保存できます。

## 判定ロジック

### 荒れる可能性

このツールでの「荒れる」の定義は
**「3着以内に単勝7番人気以下の馬が1頭以上入ること」** です。
JRA 全体でのこの発生率はおおむね 48% で、これを基準値として次の材料で加減算します。

| 要因 | 向き |
|---|---|
| 1番人気の単勝オッズ | 低いほど堅い(最大 ±20) |
| 支持率のエントロピー | 人気が割れているほど荒れる(±12) |
| 上位人気3頭の減点材料 | 休み明け・昇級・斤量増などの合計(−4〜+16) |
| 上位人気の能力 − 市場評価 | 人気先行なら荒れる(−8〜+12) |
| 頭数 | 多頭数ほど荒れる(±5) |
| レース条件 | ハンデ戦・未勝利・障害・短距離は加点、G1/G2は減点 |
| 馬場状態 | 重・不良で加点 |
| 馬場傾向と人気馬の相性 | 人気馬に不向きな馬場なら加点(−6〜+9) |
| 展開の極端さ | ハイペース/超スローで加点 |
| 伏兵の層の厚さ | 能力が人気を上回る人気薄の頭数(最大 +9) |

結果は 12〜88% にクリップされ、次のラベルが付きます。

`〜30% 堅い` / `〜43% やや堅い` / `〜57% 標準` / `〜72% 波乱含み` / `72%〜 大波乱警戒`

**50% 以上を「荒れる」と判定し、穴馬候補を3頭出力します。50% 未満なら1頭です。**

### 能力スコア(0〜100)

馬柱から次を集計し、加重平均したものをベースにします。

| 構成要素 | 重み | 内容 |
|---|---|---|
| `form` | 0.26 | 近6走の着順率(クラス格で補正、直近ほど重い) |
| `best` | 0.18 | 近走のベストパフォーマンス(能力の天井) |
| `agari` | 0.16 | **位置取り補正後の上がり3F** |
| `fit_distance` | 0.13 | 同じ馬場種別で ±200m の実績 |
| `fit_course` | 0.10 | 同一競馬場・同一馬場種別の実績 |
| `fit_condition` | 0.10 | 当日の馬場状態(良/道悪)での実績 |
| `class_fit` | 0.07 | 経験クラスと今回のクラスの差 |

`agari` は単純な上がり順位ではなく、
`(レースの後半3F − 自身の上がり3F) − 0.9 × 道中の位置取り率`
で求めます。後方から差した馬ほど上がりが速くなるのは当然なので、その分を差し引いて
**「位置取りを考慮しても速かったか」** を見ています。これにより逃げ馬が不当に低評価されません。

ここに状況補正を加減します。

* 休養明け(90/180/365日)・叩き2走目・連闘
* 斤量の増減、ハンデ戦の軽ハンデ
* 馬体重の大幅増減
* 昇級初戦 / 相手弱化
* 距離延長・短縮と当該距離実績の有無
* 継続騎乗 / 乗り替わり
* **前走の内容** — 着順以上に走っていないか(実質上がりが優秀なのに着順が悪い)、
  スローペースを後方から差した / ハイペースを前々で粘った(高評価)、
  スローペースを楽に逃げた(割引)
* 展開・馬場傾向による加減点(前述)

### 市場評価と穴指数

単勝オッズから支持率を求め、その対数の分布を
**そのレースの能力スコアの平均・標準偏差に合わせて写像** します
(生のオッズは能力スコアより遥かに分散が大きく、そのまま引き算すると
「単に人気がない馬」が上位に来てしまうため)。

```
乖離   = 能力スコア − 市場評価          … プラスなら過小評価
穴指数 = 50 + 1.8 × 乖離 + 0.30 × (能力スコア − レース平均能力)
```

穴馬候補は **単勝9.0倍以上または5番人気以下** かつ
**能力がレース平均を大きく下回らない** 馬から選びます。

## オフライン運用 / スクレイピングの作法

netkeiba へのアクセスは既定で **1リクエストにつき1.0秒のウェイト** を入れ、
取得した HTML をローカルにキャッシュします(既定 `.cache/keiba_ai`)。
ウェイトの短縮は推奨しません。取得したデータの再配布も避けてください。

社内ネットワークなどで netkeiba に到達できない場合は、
別環境で保存した HTML を使って完全オフラインで動かせます。

```bash
# 到達できる環境で HTML を保存しておく
python -m keiba_ai 202605021711 --save-html ./html_dump

# 到達できない環境ではそれを読むだけ
python -m keiba_ai 202605021711 --offline ./html_dump
```

必要な HTML は次の2種類です。

* 出馬表 `https://race.netkeiba.com/race/shutuba.html?race_id=<race_id>`
* 各馬の成績 `https://db.netkeiba.com/horse/<horse_id>/`

ファイル名は `--save-html` が付ける名前をそのまま使うのが確実ですが、
`horse_2019105283.html` のように horse_id を含む名前でも拾えます。

### 主なオプション

```
--sample              ネット接続なしでサンプルレースを分析
--max-past N          1頭あたりの参照過去走数(既定 10)
--no-form             馬柱を取得しない(高速だが精度は大きく落ちる)
--sleep SEC           リクエスト間ウェイト(既定 1.0)
--cache-dir DIR       HTTPキャッシュの保存先
--no-cache            キャッシュを使わない
--offline DIR         通信せず保存済みHTMLだけを使う
--save-html DIR       取得したHTMLを保存する
-f, --format          text | markdown | json
-o, --output FILE     結果をファイルに書き出す
-v, -vv               ログを詳しく出す
```

## Python から使う

```python
from keiba_ai.analysis.bias import parse_bias_text
from keiba_ai.pipeline import analyze
from keiba_ai.report import render

analysis = analyze("202605021711", bias=parse_bias_text("内有利で前残り"))

print(analysis.chaos_pct)            # 例: 64.1
print(analysis.chaos_label)          # 例: 波乱含み(穴馬にチャンスあり)
for e in analysis.dark_horses:
    print(e.horse.umaban, e.horse.name, e.dark_index, e.top_reasons())

print(render(analysis, "markdown"))
```

出馬表を自前で用意して分析だけ回すこともできます。

```python
from keiba_ai.analysis.engine import analyze_race
from keiba_ai.scraper import parse_shutuba, parse_horse_results

race, horses = parse_shutuba(open("shutuba.html").read(), "202605021711")
for h in horses:
    h.past_runs = parse_horse_results(open(f"horse_{h.horse_id}.html").read())
analysis = analyze_race(race, horses)
```

  cli.py            CLI
  pipeline.py       取得 → 分析までの一連の処理

  sample_data.py    --sample 用の架空レース

    client.py       HTTP・文字コード・キャッシュ・オフライン

## 制限事項

* **netkeiba の DOM 構造が変わるとパーサは壊れます。** 出馬表側はクラス名(`Shutuba_Table`,
  `HorseInfo`, `Jockey` …)、馬柱側は `thead` の見出しテキストを手がかりにしており、
  列の増減にはある程度耐えますが、大きな改修には追随が必要です。
* 出馬表 HTML のオッズは JavaScript で描画されるため空のことがあります。その場合は
  オッズ API(`api_get_jra_odds.html`)で補完しますが、これも失敗した場合は
  市場評価が使えず、荒れ度・穴指数の精度は大きく落ちます(出力に警告が出ます)。
* 騎手・厩舎の成績、調教、血統、パドック情報は評価に入れていません。
* 確率値は過去の統計を踏まえたヒューリスティックであり、実測データでキャリブレーション
  したものではありません。相対比較の目安として使ってください。
* 地方競馬・海外レースは馬柱側でクラス格を「地方」として一律に扱います。
* テキスト出力は横78桁を前提にしています。狭い画面では `--markdown` か `--json` が読みやすいです。

## 注意

* 本ツールの出力は公開データの統計的処理による**参考情報**であり、的中を保証しません。
* 馬券の購入は20歳以上。余裕資金の範囲で、自己責任でお願いします。
